# ماه‌بانو (Moonbanu) — نسخهٔ ۱٫۱٫۱

اپ کامل سلامت بانوان به‌صورت **یک پلاگین مستقل وردپرس**: تقویم شمسی، پیش‌بینی چرخه،
تحلیل الگوی شخصی، صفحه‌های همراهی همسر با حریم خصوصی سخت‌گیرانه، اشتراک ماهیانه با
درگاه زیبال و پیامک ملی‌پیامک و PWA. هیچ پلاگین جانبی (ووکامرس، فرم‌ساز، پیامک، PWA) لازم نیست.

> این اپ جایگزین تشخیص یا درمان پزشکی نیست.

---

## ۱) نصب در پنج دقیقه

۱. پوشهٔ `moonbanu` را zip کنید (یا از فایل zip آماده استفاده کنید).
۲. **پیشخان وردپرس → افزونه‌ها → افزودن → بارگذاری افزونه** → فایل zip → **نصب** → **فعال‌سازی**.
۳. یک **برگه** تازه بسازید (مثلاً «ماه‌بانو») و فقط همین شورت‌کد را داخلش بگذارید:

   ```
   [moonbanu_app]
   ```

۴. **ماه‌بانو → تنظیمات → عمومی**: همان برگه را در فیلد «برگهٔ اپ» انتخاب کنید و ذخیره کنید.
   (این فیلد برای لینک دعوت‌نامه، ایمیل‌ها و PWA لازم است.)
۵. **تنظیمات → پیوندهای یکتا** را یک بار ذخیره کنید تا مسیرهای پلاگین بازنویسی شوند.
۶. **ماه‌بانو → اشتراک و درگاه**: درگاه «زیبال» و کد مرچنت زیبال را وارد کنید. مبلغ به‌صورت
   ریال به API فرستاده می‌شود؛ اگر واحد را تومان انتخاب کنید، تبدیل انجام نمی‌شود.
   برای استفاده از زرین‌پال، درگاه را روی زرین‌پال بگذارید و merchant_id آن را وارد کنید.
۷. **ماه‌بانو → پیامک** (اختیاری): سرویس «ملی‌پیامک»، نام کاربری، API Key/رمز عبور و شماره فرستنده را وارد کنید.
۸. **فونت**: فایل‌های `Vazirmatn-400..800.woff2` را در `assets/fonts/` بگذارید
   (راهنمای `assets/fonts/README-fa.txt` یا اجرای `bash assets/fonts/download-fonts.sh`).
   بدون این فایل‌ها اپ می‌کار می‌کند و به فونت فارسی سیستم برمی‌گردد؛ فقط ظاهر دقیق طراحی
   با Vazirmatn به دست می‌آید.

### پیش‌نیازها
* وردپرس ۶٫۴ یا بالاتر
* PHP ۸٫۱ یا بالاتر (با `openssl` برای رمزنگاری یادداشت خصوصی)
* MySQL 5.7+ / MariaDB 10.3+
* فعال بودن REST API و WP-Cron (برای اعلان‌ها و چرخه عمر اشتراک)

## ۳) اشتراک و درگاه

* دو پلن: **رایگان** (ثبت روزانه، تقویم چرخه جاری، خانهٔ پایه، اعلان درون‌اپ) و
  **پیشرفته** (پیش‌بینی ۳ چرخه، تحلیل و الگوی شخصی، نقشهٔ چرخه، احتمال نشانه‌ها،
  همراهی همسر، پیامک، مرکز سلامت کامل + پرسش از متخصص، ذخیرهٔ راهنماها، بج دقت).
* جریان پرداخت: `POST /checkout/create` → رکورد `pending` + `authority` → ریدایرکت به
  درگاه → کالبک `?mb_verify=REF` → `verify` → `active` + `expires_at = now + 30 روز`
  → ایمیل فاکتور. تأیید **idempotent** است (کدهای ۱۰۰/۲۰۱ زیبال و ۱۰۰/۱۰۱ زرین‌پال پذیرفته می‌شوند).
* پس از انقضا: ۳ روز **ارفاق** (Pro فعال + بنر) و بعد `expired` (دانگرید، داده‌ها حفظ).
* تمدید یک‌کلیکی است و به باقیماندهٔ اعتبار اضافه می‌شود. درگاه‌های ایرانی پرداخت
  دوره‌ای خودکار ندارند، بنابراین تمدید همیشه با تأیید کاربر انجام می‌شود.
* واحد مبلغ: در تب «اشتراک و درگاه» می‌توانید ریال (قیمت × ۱۰) یا تومان را انتخاب کنید.

## ۴) حریم خصوصی (قاعدهٔ غیرقابل نقض)

* نشانه‌ها، خلق، درد، یادداشت خصوصی و هر داده سلامت جنسی **هرگز** به همسر نمی‌رسد.
* تنها سازندهٔ خروجی همسر `MB_Privacy::partner_payload()` است و در پایان با whitelist
  فیلتر می‌شود: رنگ ۷ روز آینده، تاریخ قاعدگی بعدی، روز تا قاعدگی، بولین هشدار PMS،
  پیشنهادهای حمایتی، وضعیت ack/snooze و چک‌لیست.
* توگل «پنجره باروری و نشانه‌ها» پیش‌فرض **خاموش** است و روشن‌کردنش فقط یک بازهٔ
  زمانی می‌دهد، نه هیچ نشانه‌ای.
* دعوت‌نامه: توکن ۱۲ کاراکتری، اعتبار ۷۲ ساعت، تک‌پذیرش، هر لحظه قابل لغو.
* یادداشت خصوصی و شماره‌ملی با AES-256-GCM رمزنگاری می‌شود. **کلید رمزنگاری الزامی است:**

  ```php
  // wp-config.php میں شامل کریں:
  define('MB_FIELD_KEY', '<۶۴ کاراکتر هگز تصادفی>');
  ```

  **اگر تنظیم نبود:** کلید از `AUTH_KEY` و `AUTH_SALT` با HKDF-SHA256 مشتق می‌شود
  (کمتر از ایدهال؛ ادمین را هشدار می‌دهیم).

  **هشدار ⚠️ حیاتی:** اگر این کلید را تغییر دهید، تمام یادداشت‌ها و شماره‌های ملی
  قبلی **غیرقابل‌خواندگی** می‌شوند. کلید باید **بخشی از بک‌آپ اجباری** باشد.
  تغییر آن بدون سیاق بازیابی منجر به ضایع‌رفتن دائمی داده می‌شود.
* هوک‌های خروجی/حذف دادهٔ وردپرس (WP Privacy API) پیاده شده است.

## ۵) لایه‌های ضدتقلب (L1…L8)

| لایه | کار |
|---|---|
| L1 | گیت سروری: رندر و route‌های Pro فقط پس از `MB_Subscription::is_pro()`، وگرنه ۴۰۳ |
| L2 | توکن HMAC-SHA256 با کلید مشتق از `AUTH_KEY` روی `uid\|site_hash\|exp(15د)` |
| L3 | کرون شبانه چند اشتراک فعال را با inquiry درگاه بازبینی می‌کند؛ ناهمخوانی → `canceled` + ایمیل ادمین |
| L4 | manifest هش SHA-256 فایل‌های `includes/*.php`؛ دست‌کاری فایل‌های حساس → **حالت ایمن** (Pro خاموش، بدون حذف داده) |
| L5 | اتصال نصب: `install_token` + هش دامنه؛ حداکثر ۲ سشن هم‌زمان همسر با heartbeat |
| L6 | نرخ‌محدود: بیش از ۵۰ درخواست در دقیقه یا ۲۰ خطای اعتبارسنجی → قفل ۱۵ دقیقه‌ای |
| L7 | هیچ راز و هیچ کلیدی سمت کلاینت نیست؛ JS فقط HTML رندرشده می‌بیند |
| L8 | kill-switch ادمین: انقضای دستی هر اشتراک + فهرست دامنه‌های مجاز |

> صادقانه: هدف این لایه‌ها **گران‌تر کردن کرک از خرید** است، نه ناممکن کردن مطلق آن.
> هر کدی که روی سرور مشتری اجرا می‌شود در نهایت قابل تغییر است؛ این ساختار کار را
> پرهزینه، پرریسک و قابل‌ردیابی می‌کند.

## ۶) PWA مستقل و اپ اندروید

* manifest از مسیر پویا و اختصاصی برگهٔ اپ سرو می‌شود و scope آن فقط همان برگه است.
* service worker نیز داخل scope برگهٔ اپ ثبت می‌شود تا با PWA دیگری روی ریشهٔ همین دامنه تداخل نکند.
* نصب فقط روی HTTPS و از همان برگهٔ اپ انجام شود؛ اگر برگهٔ اپ تنظیم نشده باشد، نسخهٔ ۱.۱.۲ آن را با مسیر `/moonbanu/` می‌سازد.
* درخواست‌های `wp-json`، `wp-admin`، کالبک پرداخت و دعوت‌نامه هرگز کش نمی‌شوند.

### ساخت اپ اندروید (WebView)
۱. در Android Studio پروژهٔ *Empty Activity* بسازید.
۲. در `AndroidManifest.xml` مجوز اینترنت را اضافه کنید:
   `<uses-permission android:name="android.permission.INTERNET"/>`
۳. در Activity:

   ```java
   WebView web = new WebView(this);
   WebSettings s = web.getSettings();
   s.setJavaScriptEnabled(true);
   s.setDomStorageEnabled(true);
   s.setDatabaseEnabled(true);
   web.setWebViewClient(new WebViewClient());
   web.loadUrl("https://YOUR-SITE.com/moonbanu/");
   setContentView(web);
   ```
۴. جایگزین سریع‌تر: با **Bubblewrap** یا **PWABuilder** از همین PWA یک APK/AAB بسازید
   (`npx @bubblewrap/cli init --manifest https://YOUR-SITE.com/moonbanu/?mb_manifest=1.1.2`).

## ۷) چک‌لیست تست

### ۷٫۱ وکتور مرجع چرخه (بخش ۴٫۴ پرامپت)
ورودی: آخرین قاعدگی `۱۴۰۵/۰۶/۰۷`، طول چرخه ۲۸، «امروز» `۱۴۰۵/۰۶/۲۷`.
انتظار:

| مورد | مقدار انتظاری |
|---|---|
| روز چرخه | ۲۱ |
| فاز | لوتئال |
| قاعدگی بعدی | ۱۴۰۵/۰۷/۰۴ (۸ روز دیگر) |
| پنجرهٔ باروری | ۱۵ تا ۲۱ شهریور |
| تخمک‌گذاری | ۲۰ شهریور |
| PMS | ۲۸ شهریور تا ۳ مهر |

اجرا: **ماه‌بانو → وضعیت** → ردیف‌های «تست جلالی» و «تست وکتور چرخه».
باید ببینید: `0 خطا از 500 نمونه` و `8 از 8 بررسی پاس شد (روز چرخه: 21)`.

### ۷٫۲ سناریوی کامل اشتراک (سندباکس)
1. «حالت سندباکس» را روشن و `merchant_id` تست را وارد کنید.
2. با یک کاربر عادی وارد `#/checkout` شوید و پرداخت کنید.
3. انتظار: بازگشت به صفحهٔ «اشتراک فعال شد»، ردیف `active` در تب اشتراک‌ها،
   رسیدن ایمیل فاکتور، باز شدن `#/analysis`، `#/cycle` و صفحه‌های همسر.
4. کالبک را دستی دوباره باز کنید (`?mb_verify=REF`): باید پیام «قبلاً تأیید شده»
   بیاید و تاریخ انقضا **تغییر نکند** (idempotency).
5. کوپن: در تب اشتراک کوپن ۲۰٪ بسازید و در `#/checkout` وارد کنید؛ مبلغ درخواست باید
   ۲۰٪ کمتر باشد و شمارندهٔ استفاده پس از تأیید یک واحد بالا برود.

### ۷٫۳ تست‌های ضدتقلب
| تست | کار | انتظار |
|---|---|---|
| دست‌کاری فایل | یک کاراکتر در `includes/class-subscription.php` تغییر دهید و پیشخان را باز کنید | هشدار قرمز «حالت ایمن»، Pro خاموش، رویداد `integrity_failed` در لاگ، ایمیل ادمین، **بدون حذف داده** |
| بازگشت | فایل اصلی را برگردانید → «دعوت‌ها و امنیت → پاک کردن حالت ایمن» | Pro برمی‌گردد، رویداد `safe_mode_cleared` |
| توکن جعلی | `GET /wp-json/moonbanu/v1/partner/home?token=ABCDEFGHIJKL` | پاسخ ۴۰۳ |
| گیت Pro | با کاربر رایگان `GET /wp-json/moonbanu/v1/analysis` | ۴۰۳ با `mb_pro_required`؛ و `#/analysis` فقط کارت فروش را نشان می‌دهد (هیچ دادهٔ Pro در HTML نیست) |
| نرخ‌محدود | ۶۰ بار در یک دقیقه `POST /checkout/create` | پاسخ ۴۲۹ و رویداد `rate_locked` |
| سشن همسر | همان حساب همسر را از ۳ دستگاه/مرورگر باز کنید | دستگاه سوم ۴۲۹ و رویداد `partner_session_limit` |
| چرخه عمر | در جدول `wp_mb_subscriptions` تاریخ `expires_at` را به دیروز ببرید و `mb_nightly` را اجرا کنید | `active → grace` (Pro فعال + بنر)؛ بعد از ۳ روز `grace → expired` (دانگرید، داده‌ها سرجایشان) |

### ۷٫۴ حریم خصوصی
1. با حساب بانو دعوت‌نامه بسازید و با مرورگر دیگر بپذیرید.
2. `GET /wp-json/moonbanu/v1/partner/home` را با حساب همسر بگیرید: پاسخ باید **فقط**
   این کلیدها را داشته باشد: `wife_name, week_colors, next_period_date,
   next_period_jalali, days_to_period, pms_alert, pms_start_jalali,
   support_suggestions, ack, snooze_until, checklist, fertility_window, disclaimer`.
3. یک یادداشت خصوصی و چند نشانه ثبت کنید؛ در پاسخ همسر هیچ اثری از آن‌ها نباید باشد.
4. «لغو دسترسی همسر» را بزنید: صفحه‌های همسر بلافاصله ۴۰۳/پیام لغو بدهند.

### ۷٫۵ رابط و دسترس‌پذیری
* در DevTools اندازهٔ ۳۹۰×۸۴۴ (و ۳۶۰×۶۴۰) را بررسی کنید: هیچ سرریز افقی نباید باشد.
* همهٔ ارقام فارسی، همهٔ صفحه‌ها راست‌چین، جملهٔ سلب مسئولیت در پای هر صفحه.
* Lighthouse موبایل روی صفحهٔ خانه: هدف ≥ ۸۵ (برای رسیدن به آن، فونت‌ها را لوکال
  بگذارید و کش مرورگر/CDN را روشن کنید).

## ۸) نکات نگه‌داری

* **کرون**: اعلان‌ها روی `mb_daily_06` (۰۶:۰۰ به وقت سایت) و چرخه عمر اشتراک روی
  `mb_nightly` اجرا می‌شوند. اگر سایت ترافیک کم دارد، WP-Cron را با cron سیستمی
  جایگزین کنید: `wp cron event run --due-now`.
* **جدول اعلان‌ها**: ستون `read` در MySQL رزرو است، پس نام آن `is_read` گذاشته شده.
* **حذف پلاگین**: پیش‌فرض داده‌های کاربران را نگه می‌دارد. برای پاک‌سازی کامل، گزینهٔ
  «حذف کامل داده‌ها هنگام حذف پلاگین» را در تب عمومی روشن کنید.
* **پشتیبان‌گیری**: جدول‌های `wp_mb_*` را در برنامهٔ بکاپ خود بگنجانید.
* **REST**: همهٔ مسیرها `permission_callback` دارند و از nonce `wp_rest` استفاده می‌کنند.

## ۹) تغییرات نسخه

### 1.0.1 — ممیزی و رفع باگ
رفع ۲۳ ایراد در ممیزی کامل کد (منطق، حریم خصوصی، امنیت، UI):

**موتور و تقویم**
1. `MB_Jalali::self_test()` مبدأ JDN را با خطای یک‌روزه می‌سنجید و همیشه «نادرست» گزارش می‌داد.
2. `sanitize_date()` از `strtotime`+`gmdate` استفاده می‌کرد و روی سرورهای با منطقهٔ زمانی غیر UTC تاریخ را یک روز جابه‌جا می‌کرد؛ حالا مستقیم از اجزای تاریخ ساخته می‌شود.
3. مرز فازها در `cycle_map()` با `phase_of_index()` هم‌خوان نبود: روز `ovul+1` در تقویم «باروری» و در نقشهٔ چرخه «لوتئال» بود. باروری تا `ovul+1` و لوتئال از `ovul+2` یکسان شد.
4. `ovulation_day()` در چرخه‌های کوتاه می‌توانست داخل روزهای خونریزی بیفتد و روز تخمک‌گذاری را حذف کند؛ کلمپ شد.
5. برچسب ماه شمسی ستون‌های نمودار «۶ چرخه آخر» با ستون‌ها جفت نبود (اندیس دو آرایهٔ مستقل). متد `recent_length_rows()` اضافه شد که طول و تاریخ شروع را با هم برمی‌گرداند.

**اشتراک و امنیت**
6. لایهٔ L2 مرده بود: `MB_License::verify_token()` هیچ‌جا صدا زده نمی‌شد. حالا رندر صفحه‌های Pro توکن امضاشده را اعتبارسنجی می‌کند و خطا در `mb_security_log` ثبت می‌شود.
7. کالبک درگاه، تطابق `Authority` برگشتی با `Authority` ثبت‌شدهٔ سفارش را بررسی نمی‌کرد.
8. محدودیت «۲ سشن هم‌زمان همسر» فقط در REST اعمال می‌شد و رندر سمت سرور آن را دور می‌زد.
9. آمار «درآمد این ماه» بر پایهٔ ماه میلادی حساب می‌شد؛ به ماه شمسی تغییر کرد.

**حریم خصوصی**
10. `/day` بلوب رمزنگاری‌شدهٔ یادداشت خصوصی (`note_private`) را در پاسخ JSON می‌فرستاد؛ حذف شد.
11. `delete_user_data()` دعوت‌نامه‌هایی که کاربر در آن‌ها *همسر* بود و متاهای `mb_partner_of`/`mb_mobile` را باقی می‌گذاشت.
12. `revoke_all()` اگر دعوت‌نامه پیش‌تر لغو شده بود متای اتصال همسر را پاک نمی‌کرد.

**دعوت همسر**
13. ساخت هر لینک دعوت تازه، دسترسی همسر *متصل* را هم لغو می‌کرد. حالا فقط دعوت‌نامه‌های پذیرفته‌نشده لغو می‌شوند (`revoke_pending_invites()`).
14. چهار توگل اشتراک‌گذاری پیش از ساخت اولین دعوت‌نامه خطای ۴۰۴ می‌دادند و ذخیره نمی‌شدند؛ حالا در `mb_share_defaults` ذخیره و به دعوت بعدی ارث می‌رسد.
15. کارت هشدار همسر متن ثابت «از فردا» داشت؛ از دادهٔ واقعی («از امروز / از فردا / از N روز دیگر») ساخته می‌شود.
16. پیام محدودیت سشن برای همسر وجود نداشت و صفحه «دسترسی لغو شده» نشان می‌داد.

**پروفایل و ادمین**
17. `POST /profile` بدون پارامتر `cycle_len`/`period_len` پروفایل را روی کف بازه (۲۱ و ۲ روز) می‌نشاند و طول چرخهٔ کاربر را نابود می‌کرد.
18. ذخیرهٔ هر تب ادمین، چک‌باکس‌های تب‌های دیگر (سندباکس درگاه و حذف داده) را خاموش می‌کرد.
19. تنظیم «متن سلب مسئولیت» ذخیره می‌شد ولی هیچ‌جا استفاده نمی‌شد؛ `MB_Plugin::disclaimer()` اضافه شد و همهٔ صفحه‌ها، ایمیل‌ها و payload همسر از آن می‌خوانند.
20. تب «وضعیت» حالا حضور پنج فایل فونت را هم گزارش می‌کند.

**اعلان‌ها و رابط**
21. فیلتر `wp_mail_content_type` به‌صورت دائمی روی کل سایت اضافه می‌شد و ایمیل بقیهٔ پلاگین‌ها را HTML اجباری می‌کرد؛ حالا فقط دور ارسال‌های خود پلاگین فعال می‌شود.
22. کرون روزانه همهٔ کاربران را در یک اجرا پردازش می‌کرد (خطر تایم‌اوت)؛ دسته‌ای ۲۰۰ نفره با ادامهٔ خودکار شد.
23. رابط: شناسهٔ گرادیان SVG در چند حلقه تکراری بود، فاصلهٔ بخش‌های حلقه به ۰٫۵۵ روز سند طراحی اصلاح شد، پنل اعلان در RTL از مرکز خارج می‌شد، و «مطالعهٔ راهنما» مقاله را با شناسه می‌گیرد (قبلاً فقط در ۱۲ مقالهٔ اول پیدا می‌شد).

# نسخهٔ ۳٫۰٫۰ — راهنمای بخش‌های تازه

فهرست کامل تغییرات در `CHANGELOG-3.0-fa.md` است. این بخش فقط کارهای لازم پس از ارتقا را می‌گوید.

## پس از ارتقا چه کنم؟

۱. پلاگین را یک‌بار غیرفعال و دوباره فعال کن (یا هر صفحهٔ ادمین را باز کن) تا `dbDelta`
   ستون‌ها و جدول‌های تازه را بسازد و کرون ساعتی یادآورها ثبت شود.
۲. به **ماه‌بانو → وضعیت** برو و **تست‌های پذیرش** را ببین؛ باید همه سبز باشند.
۳. اگر پیام «حالت ایمن» دیدی، از تب **دعوت‌ها و امنیت** manifest را بازسازی کن.
   بازسازی manifest پس از هر تغییر دستی در فایل‌ها لازم است.
۴. تب **انجمن و کوییز** را باز کن؛ سه کوییز پایه خودکار seed شده‌اند.

## ورود با کد یک‌بارمصرف (OTP)

در تب **پیامک**، سرویس را روی «ملی‌پیامک» بگذار و نام کاربری، API Key و شماره فرستنده را
کامل کن. OTP از متد `SendOtp` ملی‌پیامک استفاده می‌کند
(`https://rest.payamak-panel.com/api/SendSMS/SendOtp`). اگر پیامک ممکن نشد، کد با ایمیل
فرستاده می‌شود. کد ۲۰ دقیقه اعتبار دارد و ۵ تلاش مجاز است.

## حریم خصوصی — دو قاعدهٔ غیرقابل نقض

۱. **دادهٔ خصوصی بانو هرگز به همسر نمی‌رسد.** فیلدهای `bbt`، `mucus`، `sex`، `weight_kg`،
   `sleep_h`، `water_cups`، `exercise_min`، `meds`، `note_private`، `mood`، `pain` و
   `symptoms` در هیچ شرایطی به هیچ endpoint همسر نمی‌روند. تنها استثنای افزودهٔ نسخهٔ ۳،
   دو فیلد `pregnancy_week` و `due_date` است و فقط اگر بانو خودش توگل `share_pregnancy`
   را روشن کند. لایهٔ دوم `MB_Privacy::guard_forbidden()` است که هر نشتی را با شدت
   critical لاگ و به مدیر ایمیل می‌کند.
۲. **جملهٔ سلب مسئولیت در همهٔ صفحه‌ها.** «این اپ جایگزین تشخیص یا درمان پزشکی نیست.»
   در هر مسیر تازه هم حاضر است، از جمله بالای گزارش پزشک و پای هر نتیجهٔ کوییز.

## یادآورها و کرون

از نسخهٔ ۳، تریگرهای `period-2`، `period-0`، `pms-2`، `pill` و `partner-daily` مالک
`MB_Reminders` هستند و کرون **ساعتی** (`mb_hourly_reminders`) آن‌ها را در ساعت انتخابی
کاربر اجرا می‌کند. کرون روزانهٔ ۶ صبح برای کاربرانی که هیچ تنظیمی ندارند نگهبان
عقب‌افتادگی می‌ماند و `sent_today()` جلوی پیام تکراری را می‌گیرد.

اگر سایت ترافیک کم دارد، WP-Cron واقعی نیست؛ یک cron سیستمی روی `wp-cron.php` بگذار.

## قاعدهٔ بستن پرونده (از نسخهٔ ۳٫۱٫۲)

پروندهٔ این افزونه با نسخهٔ **۳٫۱٫۲** بسته شد. از این نقطه به بعد فقط سه چیز تغییر می‌کند:

1. **پچ امنیتی** — آسیب‌پذیری، نشت داده، دور زدن گیت Pro یا فهرست سفید همسر.
2. **باگ واقعی** — رفتاری که با سند طراحی یا انتظار کاربر نمی‌خواند و قابل بازتولید است.
3. **کارایی** — بهبودی که رفتار را عوض نمی‌کند.

هر چیز دیگری (ویژگی تازه، بازطراحی، وابستگی جدید، تغییر ساختار جدول) خارج از دامنه است
و باید در یک نسخهٔ مِیجر جدا بررسی شود. دو قاعدهٔ غیرقابل نقض تغییر نمی‌کنند:
**حریم خصوصی بانو** و **سلب مسئولیت در همهٔ صفحه‌ها**.

> یادآور اجرایی: پس از هر جایگزینی فایل‌های `includes/`، دکمهٔ «بازسازی manifest» در
> تب وضعیت ادمین را بزن (L4).
